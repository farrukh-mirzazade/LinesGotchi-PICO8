# Visual Direction

Обязательный дизайн-эталон: `assets/design/locked_reference.png`

Текущий исходный референс: `assets/design/visual_direction_v2.png`

Production-лист для переноса ассетов: `assets/design/production_sprite_reference_v1.png`

Предыдущий референс: `assets/design/visual_direction_v1.png`

Цель: привести игру к виду дизайн-эталона. Любой иной визуальный результат считается неготовым.

## Design Lock

- `assets/design/locked_reference.png` является главным визуальным источником правды.
- Все экраны должны сверяться с этим референсом перед завершением задачи.
- Нельзя менять визуальное направление без отдельного подтверждения.
- Если PICO-8 ограничения мешают повторить деталь один в один, нужно сохранить композицию, силуэт, цветовое ощущение и читаемость, а упрощение зафиксировать в документации.
- Прототипный вид из текущих скриншотов не является приемлемым ориентиром.

## Что берем

- Формат виртуального устройства: экран выглядит как отдельная портативная игрушка, а не как набор случайных панелей.
- Компактная нижняя навигация с иконками вместо длинных текстовых кнопок.
- PET-экран как маленькая комната питомца: окно, предметы, шкалы, настроение.
- PLAY-экран: поле, счет и состояние питомца читаются сразу, но не спорят друг с другом.
- STATS и RECORDS: плотные, но аккуратные панели с понятной иерархией.
- Стартовый питомец должен быть круглым/овальным, с большими глазами и хорошо читаемым ртом.
- Питомец должен иметь несколько выражений лица и состояний, а не один статичный квадрат.
- Статусы показываем иконками + короткими шкалами.
- Сетка Lines должна быть легкой: тонкие разделители, аккуратные клетки, чистый курсор, без грубых черных провалов.

## Экранные требования

- PET: питомец круглый, крупноглазый, с читаемым ртом; экран похож на уютную комнату внутри портативной игрушки.
- PLAY: поле Lines должно быть аккуратным и легким; боковая панель не должна перегружать экран.
- STATS: информация плотная, но структурная; питомец и параметры читаются без длинных объяснений.
- RECORDS: таблица рейтинга выглядит как часть той же системы, с теми же рамками, цветами и навигацией.
- Нижняя навигация везде единая: иконки, активное состояние, одинаковая высота и отступы.

## Что запрещаем

- Большие пустые темно-синие панели.
- Огромные рамки, которые съедают полезное место.
- Квадратный робот как стартовая форма питомца.
- Грубая тяжелая сетка Lines с толстыми темными клетками.
- Длинные подписи, которые не помещаются в 128x128.
- Рисование финального интерфейса одними `rectfill`/`rect` без спрайтов и тайлов.
- Один доминирующий цвет на весь экран.

## Перенос в PICO-8

1. Сначала собрать sprite sheet: питомец, иконки меню, шарики, углы рамок, декоративные элементы.
2. Затем пересобрать экраны из тайлов и спрайтов.
3. Координаты UI зафиксировать по 128x128, без элементов за пределами экрана.
4. После каждого визуального прохода проверять скриншотом в локальном PICO-8.
5. Скриншот из PICO-8 сравнивать с `assets/design/locked_reference.png` перед тем как считать визуальную задачу закрытой.

## Следующая реализация

Нужно перенести design lock в PICO-8:

- насколько круглый питомец читается в реальном размере PICO-8;
- можно ли упростить комнату без потери характера;
- достаточно ли легкая сетка Lines для долгой игры;
- какие элементы сразу переносим в sprite sheet 8x8/16x16;
- какие цвета заменить на ближайшие из стандартной палитры PICO-8.
